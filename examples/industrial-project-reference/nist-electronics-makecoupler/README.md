# NIST electronics MakeCoupler reference

This reference follows the complete selected MakeCoupler activity in Iteration1 of NIST's electronics assembly case study. It is a useful next step after block and port structure: the original author diagram, explanatory diagram, engineering English, editable draw.io file and source ledger cover the same 17 calls, 16 directed ControlFlow edges, 33 input pins, 25 output pins and two activity parameter nodes. Two owned activity parameters are also inventoried in the ledger.

Read 01–08 down the left column, follow the arrow through the center corridor, then read 09–17 down the right. Inputs calls GetInputs_Coupler and exposes nine typed component outputs. UnitAssembly calls Assemble with an input typed Part and an output typed Coupler. Assembly and manual inspection alternate before leak checking and functional testing. Vibration, burn-in and final-data tests follow, then manual verification, laser marking, touch-up, two separately named final-sell inspections and PutOutputs_Coupler. Distinct call instances remain distinct even when they call the same behavior, such as Assemble or ManualInspect.

The 16 arrows are exactly the native ControlFlow edges. They order calls. The selected source has no ObjectFlow edges, so neither parts nor work orders are carried by those arrows. Every pin and both activity parameter nodes remain unwired in this reading. workOrderIN is untyped in the source and remains untyped. Displayed multiplicities are 1. Do not fill these gaps to make the drawing appear more executable.

INCOSE IW2021's Production and Logistics challenge-team presentation identifies the electronics assembly case and industry contributors; it describes models for design and operational decisions. This establishes an engineering case study, not a deployed physical installation. The source activity is a longer linear operational sequence, not evidence that the pack now covers complex operational breadth.

Independent validation rereads the original native XML, checks every node/pin/owner/type/multiplicity/call/parameter and every flow, compares editable geometry and labels, and rejects seven meaningful mutations. Rendering checks actual font boxes and canvas/owner clipping. Native MagicDraw model loading/round-trip, execution equivalence, object-flow completion, simulation and a full SysML v2 conversion remain unrun or unestablished. Many called activities have no internal edges. The source's open semantics are retained.
