# TMT APS: requirement, formalization and equality bindings

Saved parser/native/render reports describe historical checks on their exact inputs; this packaging change does not rerun them or independently validate original sources. Public current checks establish reviewed-derivative correspondence only.

Requirement TMT_ID `REQ-2-APS-0017` names Alignment Maintenance time; imported class ID is `_2ca33d85-e793-40fa-9f3a-b3c90e37fd87__17_188f7b22-cc8f-4e5c-b35c-8e3fc63198fb`.

**Adapted English:** APS must support on-axis alignment in less than 30 minutes, at a single elevation angle, when the optics are within the alignment maintenance specifications. Time alone does not cover those other conditions. Original text remains in the linked native authority and local evidence; the public contract uses a bounded paraphrase.

**Original formalization:** Maintenance Alignment Maximum Time has maintenanceAlignmentTimeLimit default **1800.0 seconds**. The v2 transcription uses an overridable initial value, `default := 1800.0`, following [OMG Transformation section 7.7.4.2.10](https://www.omg.org/spec/SysML/2.0/Transformation/PDF#page=303), rather than a fixed binding. MaxTimeConstraint's rule `_18_0_2_baa02e2_1429562376320_828902_151514` is exactly `p1<=maxTime`. Equality bindings link maxTime to the limit and p1 to PEAS.tFinal. The maintenance FinalDiffTime effect sets tFinal from t1-t0, an elapsed duration; its implementation stays opaque.

**Preserved discrepancy:** English uses a strict boundary; the mathematical model uses a non-strict one. At 1800 seconds the source constraint passes and literal English timing does not. The view, v2 predicate and checks preserve this difference without silently changing <= or asserting full requirement satisfaction. July 2016 has a 3000-second class default; older stored instance slots also occur. This example selects the February **class default** and matching published 1800-second view, not an old simulation instance.

Figure 7 documents manual formalization. The selected archive corroborates requirement, predicate, default and bindings; exact publication layout and its particular graphical refine link are not claimed verified. The new schematic therefore draws only verified equality bindings, without inventing a v2 satisfy/refine assertion.
