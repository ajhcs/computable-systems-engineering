# TMT APS: concurrent exposure command and acknowledgement

The engineering question is how a command, its input and acknowledgement relate. [Herzig et al., 2017, Figure4 / section2.4, page6](https://www.omgsysml.org/TMT-APS_AO4ELT17_AnalyzingBehavior_final.pdf#page=6) shows an Activity, with adjacent English explaining command and acknowledgement signals. [Original native model](https://github.com/Open-MBEE/TMT-SysML-Model/blob/87832a1657ccab023a90a6acfd0dff02d60e2b46/TMT.mdzip) is February27,2017, SysML1.4 / MagicDraw18.0, archive SHA256 eb54c3105e4d894bb06378476f364bbf5cdb3bfad4cbf55f10fefacf6cad515f. Activity ID: _17_0_2_3_41e01aa_1377716303952_671385_42761. Diagram ID: _17_0_2_3_41e01aa_1378924172312_463799_43173. Exact publication export commit is unverified.

**Source reading:** Initial node reaches a fork. One branch sends SH_Take_exposure_Cmd via the original untyped PEAS2SHOut port. The other accepts SH_Take_exposure_Ack. Both flow into a join, then the Activity final node. The Integer input dit flows to send argument p; the command signal has an Integer dit property. All six ControlFlows and the one ObjectFlow are retained. Serializing send then accept, replacing the join by a merge, or supplying a timeout would change this selected meaning.

The paper describes an image payload, but the selected native Ack signal has no owned payload attribute. Preserve that gap. dit has no unit or bound in the selected primitive type; do not invent seconds, positivity or exposure duration. The accept action has no specified receiving port; do not mirror the send port into it.

**Derived v2:** Signals become item definitions; the input object flow is represented by the command constructor argument. Fork, join and six control successions are retained and checked against actual linked pilot elements. The original reusable Activity owned under Cmd_SH becomes one nested action usage inside a new lexical PEASContext so the original onPort can resolve. That is a declared representational change, not a claim of complete ownership migration. External interface behavior, queues, all other activities and action implementation remain outside this slice.

**Rendering:** The source-style view redraws selected v1 Activity glyphs, with source IDs on nodes and edges. It is a simplified reading, not a native Cameo export or a v2 graphical-conformance result. Its draw.io file is editable presentation with embedded send/accept stencils; XML/endpoints are checked, but an actual draw.io edit/save/reopen round-trip is unrun.

The actual pinned Pilot2025-09 native ACTION renderer produced PlantUML from parsed v2. Default SVG returned an error-placeholder image because dot was absent. We retained generated PlantUML and used bundled Smetana explicitly for the actual SVG/PNG; rendering emits YMirror warnings. Its fork/join and branch order are visible, but the via PEAS2SHOut annotation is absent and dit's input glyph is unconnected. Do not hand-correct this output and label it native. UUID links are generated, not original stable source IDs.

**Validation:** Parser/linking/static checks pass with no findings and zero compiled CSE obligations. Native linked inventory resolves PEAS2SHOut and Ack type and retains six successions. Source XML, ledger, geometry, SVG and draw.io endpoint correspondence are checked, with negative cases for serialized control, missing object flow, invented receive port, changed port and lost join. These results do not establish behavioral execution or full v1/v2 equivalence.

A separate actual expression-evaluator check on the accepted TMT timing derivative returns true,true,false at 1799,1800,1801 seconds. This confirms the inclusive formal predicate, including its disagreement with strict paper English at1800. It is a pure expression check on supplied numbers, not simulation or measured instrument behavior. [Source notices](../engineering-reference/notices/README.md).
