# Computable Systems Engineering

Use the relevant skill and record contract. For connected work, use `coordinate-engineering-work`, share one model and check each affected view. A concept and scenario can be delivered on their own.

Preserve engineer-approved intent, applicability, obligations and quantitative limits. Propose changes to meaning for the engineer to decide. Start with [the verification brief](docs/first-version-brief.md) when changing semantics. Keep the skills independently runnable and update both CONOPS and scenario helper copies together.

Use bounded, deterministic checks on declarative records. A required review passes only when each required check passes. Report draft shape, qualified execution and engineering acceptance with their own evidence. Run `python3 scripts/check.py` for regressions.

Follow the [diagram skill](skills/generate-engineering-diagrams/SKILL.md) for diagram or reference-library work. Preserve model meaning, source versions and explicit view labels. Keep private sources, annotations, course materials, user models and credentials out of Git. Use synthetic or attributed public fixtures.

For user-facing flows and operational handoffs, follow the [interaction walkthrough](docs/interaction-walkthroughs.md). Use relevant precedents and review a low-fidelity flow and its model mapping with the user before substantial expansion or implementation.
