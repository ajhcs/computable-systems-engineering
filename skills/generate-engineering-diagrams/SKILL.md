---
name: generate-engineering-diagrams
description: Generate and review source-grounded engineering diagrams using matched human-engineered references, traceable models and actual rendering checks.
---

Use this skill to produce or critique a diagram from supplied or existing accepted engineering meaning. It is a diagram-generation reference skill/library. New system-model design, requirements, assumptions, thresholds, allocations and engineering acceptance remain with the engineer. Selected v1-to-v2 reference transcriptions are explicitly scoped derivatives; do not invent a new system merely to fill a diagram family.

1. Read the actual project model, source version and applicable repository guidance. Establish the engineering question, selected IDs and boundaries. Read [the source-selection guide](../../docs/engineering-references.md) and [coverage/gates](../../docs/diagram-reference-coverage.md). Select the closest matched [TMT/APE reference](../../examples/engineering-reference/README.md) or [Action extension](../../examples/engineering-reference-extension/README.md); original model, author English and original diagram come first. If the source does not establish a relation, expose the gap. Keep raw/private notes and figures in ignored work paths.
2. Freeze a semantic ledger before drawing: ownership/containment, endpoint direction, multiplicity, visibility, port kind, event/guard/effect, initial/final/fork/join types and numerical units/default/binding distinctions. Use source IDs across text/model/geometry. Clearly label original v1, derived v2, actual native-tool view, simplified model-derived presentation and generic explanatory graph. A generic graph is not a formal SysML diagram.
3. Derive the view from the selected meaning. Read [matched style prototypes](../../examples/diagram-style-prototypes/README.md) for optional presentation treatments. Change styling only after meaning is locked. Preserve formal glyphs and distinguish control/object flow, definition/usage and composite/substate exits. Do not use image generation for formal graph content. SVG and draw.io are presentation artifacts; draw.io is not lossless SysML interchange.
4. Validate with available native tooling and meaningful source-fidelity checks. Run the pinned parser on v2 text and the required repository suite. Parse/linking acceptance is not behavioral correctness. Inspect actual rendered pixels, including error-placeholder detection, clipping, endpoints and annotations; renderer APIs can return SVG even when it is an error image. Record any omitted semantics in tool-generated views. Native editor edit/save/reopen is a distinct unrun gate unless actually performed. Only claim computation/simulation for a named engine, defined supported semantics, supplied inputs and independently expected results.
5. Deliver the diagram image, concise engineering reading, model and source links, editable artifact where useful, validation receipt and unresolved limits. Compare source/baseline and changed renderings using the same selected IDs. For style reviews use matched views and structured text alternatives; narrow screens should allow readable scrolling rather than shrinking formal labels. Do not declare faster comprehension or a winning style without review.

Use python3 scripts/check.py --require-sysml when the pinned parser is installed; do not upgrade the parser silently. Available bounded source checks are scripts/engineering_references.py --check, scripts/check_engineering_references.py and scripts/check_exposure_reference.py. Native probe source in tools/sysml/Reference*Probe.java documents actual pilot visualization, linked-element and expression-evaluation routes. A numerical constraint evaluation is not a state-machine simulation.

This skill runs in the complete repository/plugin checkout and links shared references/tools. Copying this folder alone does not install the reference library or parser. No publication or source-rights grants are implied.

Native-v2 styling proof: see [the actual composition TREE reference](../../examples/native-v2-composition/README.md). Extract linked facts and native output in one session; native UUIDs change between parses. Preserve all non-color SVG primitives and validate source roles, ownership, bounds and endpoint diamonds. Keep source-v1 redraws and incomplete native views explicitly labeled. For incomplete Action/State/Interconnection/Sequence families, [renderer contracts](../../examples/native-v2-composition/renderer-contracts.md) require resolved, traced parsed-v2 facts; preflight is not image-fidelity validation.

Use [reference reading and validation guidance](../../docs/diagram-reference-reading-guide.md) for reader-first alternatives, explicit annotation ownership, source-matched scope and independent rendering gates.

Engineering research reference additions: [xPPU and NIST Wireless](../../examples/industrial-project-reference/README.md) provide bounded matched composition and port-topology references. Their qualification ledger records applied stereotypes, archive revisions, external profiles and source-specific rights. Preserve private inherited visibility; expose failed linking and explicit view-context lifts. Readings, actual pilot views and formal textual models retain distinct labels.

Operational source reference: examples/industrial-project-reference/nist-electronics-makecoupler/README.md matches an original formal SysML 1.x activity with its complete selected explanatory reading. Preserve call identity, the native ControlFlow/ObjectFlow distinction, all pins and source gaps. Never turn an unwired pin, an edge name or an empty called behavior into an invented data flow, executable guard or implementation.
