# FRET reuse spike (2026-09-29)

Scope: inspect the upstream [FRET compiler interface](https://raw.githubusercontent.com/NASA-SW-VnV/fret/master/fret-electron/app/parser/FretSemantics.js), [CLI manual](https://github.com/NASA-SW-VnV/fret/blob/master/fret-electron/docs/_media/cli/cli.md), [installation guide](https://github.com/NASA-SW-VnV/fret/blob/master/fret-electron/docs/_media/installingFRET/installationInstructions.md), and [realizability guide](https://github.com/NASA-SW-VnV/fret/blob/master/fret-electron/docs/_media/exports/realizabilityManual.md). This is an interface and dependency feasibility probe, not a successful runtime integration. The upstream `master` pages were inspected on this date; no revision was pinned because nothing was imported.

The compiler exports `compile(text)` and returns either `parseErrors` or collected semantics. It depends on ANTLR, generated lexer/parser files, a semantic analyzer, and support utilities; extraction of one file would not be standalone. Quoted free-form text is deliberately not formalized. The CLI offers `formalize` (FRETish to temporal-logic formula) and `realizability` on a stored project/component. The latter calls Kind 2 or JKind and requires Z3 plus other configured tools. These functions cover temporal requirement formalization and a stronger realizability question than this increment's single-instant consistency test. They do not supply this model's declaration, unit, trace, or step-data checks directly.

The documented install needs Node, Python, build tools, and Electron system libraries; realizability adds solver dependencies. Node/npm were present locally, but the FRET CLI was not installed. Network access from this checkout could not resolve GitHub, so no clone, install, execution, runtime measurement, or version-specific integration test was performed. The repository reports FRET 3.x under Apache-2.0; redistribution would require its license and notices. No FRET code or dependency is included here.

Decision for this alpha: keep the standard-library finite checker. Its small predicates and step semantics do not need the FRET compiler, and a translation to FRETish would add semantic mapping risk without demonstrated benefit. Revisit on a temporal requirement that cannot be represented honestly here; pin an upstream commit, run the CLI, test translation equivalence on examples and failures, and record the install/license obligations before adoption.
