# Definition-owned and retained-role inspection

This development path extends inspection within physical composition and
selected configuration. The shared projection, saved reader, local controller,
CLI and site callbacks expose declaration and retained-role occurrences.
Assembled qualification is recorded separately in the parity matrix; MCP,
the ChatGPT component, private hosted persistence and actual application
journeys remain open. The inspect row stays active.

## Existing authority

Use the existing [native configuration contract](../configuration-review.md),
saved registry and complete revision-bound findings. A part declared by `Base`
remains owned by `Base` when `current : Assembly` selects it through type
inheritance. It cannot become a native child of `current` merely because it
appears in that selected context.

The existing checker refuses a historical role redefined by the selected type
or usage. Inspecting the overriding declaration cannot adopt a new retained
selection. Optional, suppressed and unsupported bounds keep their respective
unknown, failed and unsupported outcomes. A missing binding has no inferred
native UUID. An external peer in `configuration-1.1` has no selected ownership
parent; its native declaration and reference/composite fact remain explicit.

Retain the whole review, including connection findings and omissions when the
connected profile is supplied. A selected row cannot narrow required scope or
replace the full result. The existing [current-system view](../configuration-system-view.md)
remains a separate projection with its own contract.

## Source and projection work

The shared read projection uses the saved `CompositionDocument`, its
registry, native inventory, exact scope files and existing reconciliation
reports. It supplies no second inheritance or selection verdict engine.

Native declaration rows, retained selected roles and external peers remain
separate. Each occurrence retains its origin, view/context, native UUID
when resolvable, exact native identity and owner, direct type, multiplicity
status/source, short ID and redefinition links. A retained role also needs its
file/digest, logical role ID, requested parent/type and per-ID findings. Preserve
the complete overall report independently of each row's result.

Presentation occurrences remain distinct from engineering UUIDs. The same
declaration can appear as a frame, declaration row and retained-role occurrence.
Unresolved logical roles remain inspectable without inventing native edit
targets. Ownership comes from the native inventory, including quoted names.

`verifier/composition_inspection.py` supplies this projection to the existing
view builder. Frame descriptors preserve their existing fields. Declaration
occurrences bind the persistent UUID; scope occurrences bind the exact file,
scope digest, kind and logical ID. A shared rename leaves the old role binding
unresolved until an explicit scope decision; it does not transfer that role to
the renamed declaration automatically.

## Direct interaction and fidelity

Keep the [native ownership diagram](composition-diagrams.md) and its original
kit. Source-linked declaration and retained-role tables can sit beside it.
Their position and row order create no ownership edge. Preserve exact masters,
fonts, swatches, labels and reading scale under the
[SVG fidelity contract](composition-svg-fidelity.md).

The main inspector shows engineering properties and distinguishes the native
owner from the selected parent/context. Protocol UUIDs, occurrence tokens and
digests belong in inspectable context details. Native bounds and unresolved
statuses remain visible.

Provide pointer and keyboard selection, readable table scrolling and an
explicit return to a retained draft. That return must restore the exact target
and focus/reveal its input or occurrence. Selecting another occurrence of the
same UUID cannot retarget the draft. A disappeared occurrence retains its
values visibly and requires explicit resolution.

A row without a diagram frame has no frame geometry. Move/resize controls must
explain that applicability; they cannot move another occurrence implicitly.
Native semantic edits remain applicable according to the selected declaration's
kind and the existing operation contracts.

The local controller captures both the native UUID and inspection occurrence.
Each form draft retains its operation kind, so another form cannot consume its
values. A refused preview leaves a visible discard path. Lost-save reload keeps
the exact request, raw fields and original target pair, including when the saved
edit makes that logical role unresolved. Whole-project restoration remains
available from an unresolved selection; semantic edits require a native target.

The reader pages declaration and scope tables in groups of 25. Keyboard paging
focuses the corresponding enabled page control or a returned row. The bounded
read API pages by origin, with limits from 1 through 100, without changing full
review scope. For a saved local project:

```sh
python3 scripts/composition_project.py inspect-view --project work/private-composition.git --view-id PC_CONTEXT --origin selected_role --offset 0 --limit 25 --expected-revision 1
```

The result includes the captured revision, commit and source bundle digest.
Supply `--expected-bundle-sha256` to bind a subsequent read to that source.
The authenticated `POST /api/inspection` and
`cse_list_inspection_occurrences` callback use the same projection and page
helper. These local paths do not establish MCP or actual-host parity.

## Complete the operation across interfaces

| Work item | Required realization and acceptance |
|---|---|
| Shared projection | One authoritative read result for CLI, saved export, loopback state, site tools, MCP and the ChatGPT component; exact source/scope/registry bindings and complete findings. |
| Reader selection | Select frames, declaration rows and retained-role occurrences through the same selection API; preserve native UUID versus occurrence and selected-context distinctions. |
| Workbench target | Capture UUID, occurrence, revision and raw fields. Preserve them through inspection, refresh, stale guards, pending/unknown saves, return/discard and exact retries. |
| Native edits | Route row-origin rename and multiplicity edits through the existing native candidate and transaction. Reparse, retain other facts/bytes, validate all declared views and recheck unchanged scope. A shared rename cannot retain a stale scope pass. |
| Tools | Supply the same properties and target semantics through CLI, MCP, site and component operations. Refuse layout on an unframed row; selection is not scope acceptance. |
| Persistence/export | Derive tables again from exact saved sources, registry and scope. Bind exported role data to its revision/checker; check reconstruction, changed-source refusal, restart, monotonic restore and cross-application reopen. Selection remains transient. |
| Full coverage | Retain larger/paginated sets, multiple scopes, nested role parents, direct/inherited/type-owned/usage-owned and external declarations, quoted names, partial failures and currently unsupported inheritance/variation cases. Do not reduce existing profile limits. |
| Actual hosts | Run the assembled workflow in both Codex and ChatGPT against the same private durable project. Local browser and synthetic host evidence cannot close these cells. |

The [native source/transaction](composition-persistence.md),
[connected interaction](composition-interaction.md) and
[site adapter](composition-site-tools.md) remain the implementation starting
points. Any supporting persistence or host work must identify the role-inspection
acceptance case it completes; it is not an independent infrastructure milestone.

## Reusable synthetic fixtures and proof limits

[The fixture set](../../tests/fixtures/composition-role-inspection.json) retains
nine explicit model/scope pairs and independently specified expected checked
IDs, statuses and rule IDs: inherited selection, a redefined historical role,
explicit overriding selection, optional/suppressed/unsupported bounds, a missing
binding, mixed row/overall outcomes and an external referenced peer. It also
retains the negative source view that must refuse an inherited role as a native
ownership child. These are software fixtures, not accepted system designs.

The historical disconnected proposal was checked at desktop and narrow widths, including
same-UUID/different-occurrence drafts, keyboard return focus, original DejaVu
glyph suppliers and unchanged source/scope bytes. Astra's return-focus finding
was repaired and reviewed. Those observations establish the proposal's named
scope; they do not prove connected row editing, recovery, MCP, actual hosts or
complete physical-capability parity. Connected checks are
`tests/test_composition_inspection.py`, the authenticated session tests and
`tests/browser/composition_roles.mjs`. Keep their source-bound execution receipts
separate from that proposal and from actual application acceptance.
