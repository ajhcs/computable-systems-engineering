# Definition-owned and retained-role inspection

This is the next inspection contract within physical composition and selected
configuration. Its source-bound walkthrough has been reviewed; production row
selection and editing are not implemented yet. Existing frame inspection and
native ownership validation retain their current behavior. The inspect row in
the parity matrix stays active.

## Existing authority

Use the existing [native configuration contract](../configuration-review.md),
saved registry and complete revision-bound findings. A part declared by `Base`
remains owned by `Base` when `current : Assembly` selects it through type
inheritance. It cannot become a native child of `current` merely because it
appears in that selected context.

The existing checker refuses a historical role redefined by the selected type
or usage. Inspecting the overriding declaration cannot adopt a new retained
selection. Optional, suppressed and unsupported bounds keep their respective
unknown, failed and unsupported outcomes. A missing binding has no inferred
native UUID. An external peer in `configuration-1.1` has no selected ownership
parent; its native declaration and reference/composite fact remain explicit.

Retain the whole review, including connection findings and omissions when the
connected profile is supplied. A selected row cannot narrow required scope or
replace the full result. The existing [current-system view](../configuration-system-view.md)
remains a separate projection with its own contract.

## Source and projection work

Add one shared read projection over the saved `CompositionDocument`, its
registry, native inventory, exact scope files and existing reconciliation
reports. Do not implement a second inheritance or selection verdict engine.

Represent native declaration rows, retained selected roles and external peers
separately. Each occurrence must retain its origin, view/context, native UUID
when resolvable, exact native identity and owner, direct type, multiplicity
status/source, short ID and redefinition links. A retained role also needs its
file/digest, logical role ID, requested parent/type and per-ID findings. Preserve
the complete overall report independently of each row's result.

Use stable presentation occurrences distinct from engineering UUIDs. The same
declaration can appear as a frame, declaration row and retained-role occurrence.
Unresolved logical roles remain inspectable without inventing native edit
targets. Do not split quoted native names to derive ownership.

## Direct interaction and fidelity

Keep the [native ownership diagram](composition-diagrams.md) and its original
kit. Source-linked declaration and retained-role tables can sit beside it.
Their position and row order create no ownership edge. Preserve exact masters,
fonts, swatches, labels and reading scale under the
[SVG fidelity contract](composition-svg-fidelity.md).

The main inspector shows engineering properties and distinguishes the native
owner from the selected parent/context. Protocol UUIDs, occurrence tokens and
digests belong in inspectable context details. Native bounds and unresolved
statuses remain visible.

Provide pointer and keyboard selection, readable table scrolling and an
explicit return to a retained draft. That return must restore the exact target
and focus/reveal its input or occurrence. Selecting another occurrence of the
same UUID cannot retarget the draft. A disappeared occurrence retains its
values visibly and requires explicit resolution.

A row without a diagram frame has no frame geometry. Move/resize controls must
explain that applicability; they cannot move another occurrence implicitly.
Native semantic edits remain applicable according to the selected declaration's
kind and the existing operation contracts.
