# Physical composition visual baseline

The workbench uses the existing engineering SVG and iconography guidance.
The weeks of kit development remain source material for this capability.

The current walkthrough uses the saved `palette-rectangle-white-plain` master,
not a newly drawn approximate frame. Its two source `use` treatments and
stroke are retained; dimensions and occurrence IDs are adapted to the text.
Source specimen words are replaced with independently editable native-bound
labels. `composition-kit-usage.json` records the exact master and font manifest
hashes, selected N0/N100 swatches, model binding and allowed adaptations.

The saved DejaVu Sans/Mono files, metrics, manifest and copyright notice are
preserved byte-for-byte from the historical kit. Text is not stretched. Gray
UI chrome expresses the rough interaction proposal; it creates no engineering
category. The diagram uses the existing unarrowed hierarchy convention.

Use the catalog to inspect exact IDs before selecting another component.
Illustrations do not create model elements. Formal glyph meaning, native owner,
relationship endpoints, labels, counts and units remain independently checked.
No illustrative icon is added where the current question needs only a frame.

The [full saved design-kit workflow](../../skills/generate-engineering-diagrams/references/design-kit.md)
is preserved verbatim from revision G and is required by the diagram skill.
It covers the palette page references, original artwork, boxed labels, textures,
fonts, exact swatches, document tables and rendered comparison procedure.

The complete revision G readable-presentation guidance is also preserved
verbatim. Its connector-label placement, drawing-identification tables, intended
reading size, detail-sheet coverage and explicit overview requirements remain
part of this capability's target. The initial local reader does not yet provide
all of those interactions or exports; preserving plain frames alone cannot close
the visual cells in the parity matrix.

physical-composition visual parity.

The saved-native physical renderer now reuses the original font/template helpers
without changing their bytes; [source pins](composition-kit-source.json) retain
that provenance. The preserved spacecraft source, layout, labels and appearance
produce a pixel-identical graph crop in the assembled renderer. This is one
matched source/graph comparison, not full document or capability qualification.
The [diagram contract](composition-diagrams.md) separates that evidence from
new literal-bound display, current reader behavior and remaining parity work.
