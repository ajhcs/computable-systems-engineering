# Capability completion ledger

The workbench is in development. Physical composition and selected configuration
is the only admitted capability. No capability is qualified as complete.

`parity.json` is the operation-level delivery ledger. Its layers cover source,
meaning, visuals, direct interaction, each agent/application interface,
persistence, validation and exports. `entrypoints.json` preserves command
declarations found across main, the supplied dirty checkout, the historical
diagram work and the hosted branch. Semantic reconciliation of that union is
still in progress; declarations are not a completeness or execution proof.

Run `python3 scripts/workbench_parity.py` for ledger consistency and evidence
freshness. Run it with `--require-complete` for the release gate. A consistent
incomplete ledger passes inspection and fails the release gate. This checker
does not authenticate results or engineer acceptance.

Only one capability can be active. A later capability cannot become active or
close while an earlier one remains open. Shared changes reopen affected evidence
when its bound source hashes no longer match. Required host or visual evidence
cannot be replaced by a backend test.

## Physical composition increment

The admitted scope is the union of existing composition and configuration
support, including literal multiplicity and supported inherited/redefined
selection. The older five-family renderer's narrower exclusions are interface
gaps to close, not permission to remove existing engineering support.

The implementation exposes Pilot-resolved declaration/name/reference/document
ranges, explicitly in UTF-16 coordinates. `scripts/composition_edit.py` inspects
one source or an explicit text bundle and prepares a rename using those ranges.
An independent reparse checks all extracted native facts and resolved reference
correspondence. Engineering IDs and project registry IDs survive the operation.

This candidate boundary does not save or commit a project. Remaining linked
analytical adapters, create/reparent/delete/property editing,
the graphical editor, host adapters, remote durable history, cloud storage and actual
application acceptance remain open matrix cells. Supported documentary binding
updates are part of the same immutable candidate: native CSE workflow/view
records and linked presentation labels. Plain prose, labels, logical IDs,
unaffected files, original spacing and line endings are preserved. An unknown
structured record is refused when its binding semantics are unavailable; that
is an open adapter obligation, not a reduced target support boundary.

Retained configuration scopes keep their exact bytes and digest. A candidate
lists affected scope paths for reconciliation and reruns the existing native
configuration checker. A stale native binding cannot keep an earlier pass,
including after reconstructing the candidate with its registry. This does not
accept new scope bytes or infer selection from a rename.

A [local Git transaction reference](composition-persistence.md) now persists
this candidate path, its registry and supported companions. It provides atomic
head publication, monotonic restoration and retry receipts. Local process
restart and portable Git history are checked; remote persistence, initialization
recovery and application acceptance remain open. The selected bare Git directory
is server-side storage, not a filename supplied inside a model bundle.

The [saved physical diagram path](composition-diagrams.md) now renders native
definition hierarchies and usage composition with literal bounds, exact
unresolved-bound syntax, original SVG frames and saved DejaVu typography.
The reader selects and inspects actual element bindings. Its
[overview/readable navigation](composition-navigation.md) operates on that same
saved SVG in the editor and standalone CLI artifact, with a corresponding site
callback; native fonts and stored geometry retain their reading-size authority.
Layout transactions
preserve SysML and identities; connected graphical editing remains open.

For the explicit bundle transport, see [the bundle contract](composition-bundle.md).
Bundle file names label supplied texts; they are never instructions to read or
write another disk path. The source mapping retains each file's original text.

Project registry entries map durable UUIDs to exact native identities. Import
assigns IDs under a project UUID; subsequent commands must preserve the saved
registry. An externally changed source that disagrees with the registry requires
explicit reconciliation. Source hashes here identify candidates; they are not
the monotonic project revision needed for durable transactions and undo.

## Preservation

`scripts/workbench_inventory.py` writes an exclusive-create source receipt to a
selected ignored directory. It records every tracked and nonignored untracked
file's hash or symlink text, Git HEAD, dirty status and command declarations.
It follows no symlink into private material and stores no raw sources.

Keep machine-specific receipts in `work/workbench/`. Preserve all original
worktrees. Reuse historical diagram code and the revision G kit through a
reviewed integration; fresh assembled verification remains required.

The [local connected interaction](composition-interaction.md) adds explicit
preview/save, native rename, finite multiplicity, frame move/resize and whole-snapshot restoration
over the same project. Its loopback transport and embedded saved reader are
development implementations. The [site adapter](composition-site-tools.md)
registers selection, preview/save, refresh and receipt recovery around those
same controls when `document.modelContext` is available. Synthetic host-API
browser checks are distinct from actual host execution. Hosted authorization,
full operation coverage, MCP/MCP Apps and actual application journeys remain open.
