# FHWA highway-merge slice: translation proposal

Source: [FHWA-HRT-20-064, *Detailed Concept of Operations*, December 2020](https://www.fhwa.dot.gov/publications/research/operations/20064/20064.pdf), Chapter 3, printed pages 25–33. The online PDF begins with a [February 9, 2021 errata](https://www.fhwa.dot.gov/publications/research/operations/20064/20064.pdf) correcting the Table 1 note and adding a reference on page 107. Retrieved 2026-09-29. No source PDF is distributed here.

The source's Table 7 links need BT-N1.03 (gather, integrate, process, and disseminate data) to requirement BT-R1.08. BT-R1.08 states that an ADS-equipped Cooperation Class B or higher vehicle can broadcast an intended future driving path for **at least the next 15 seconds**, at **approximately 3-second intervals**. Chapter 3's highway-merge sequence describes ramp-vehicle notification, a transition to an acceleration lane, use of predicted path data by mainline vehicles, and a termination broadcast (printed pages 25–28). [Source PDF](https://www.fhwa.dot.gov/publications/research/operations/20064/20064.pdf).

[The JSON proposal](../examples/verifier/fhwa-merge-proposal.json) formalizes only the lower bound on future-path horizon and a two-step illustrative data flow. It maps Class B and C to the source phrase “Class B or higher” within a deliberately finite B/C set. The bound `max: 30` is an **analysis cutoff**, not a source-imposed maximum; thus this toy domain cannot explore longer horizons. The record does **not** formalize broadcast frequency, reception reliability, distance, merge safety, or the full notification sequence. “Approximately every 3 seconds” lacks a tolerance in the cited passage, so no exact interval is invented. The scenario's completion is an illustrative model endpoint, not proof that a real merge completes. Its initial and effect values are authoring assumptions requiring engineer review.

`python3 scripts/verify.py examples/verifier/fhwa-merge-proposal.json --review` checks this proposal's internal declarations, trace shape, supported consistency, and finite scenario path. A pass does not accept the translation or establish FHWA endorsement, physical feasibility, or implementation behavior.
